# 각궁 공방 대소동 (가제) — GAME_DESIGN

> 상태: 비교용 프로토타입 기획안. 실제 각궁 제작의 역사적 재현이 아니라 제작 소재를 활용한 캐주얼 게임이다.

## 1. 한 줄 기획

오버쿡드에서 영감을 받은 **1인용 탑다운 3D 공방 게임**. 플레이어가 재료를 옮기고 작업대를 가동해 제한 시간 안에 각궁 주문을 완성한다.

- 장소: 부천활박물관 체험용 태블릿
- 대상: 초등학생
- 플레이: 약 3~5분
- 기술: JavaScript + Three.js(WebGLRenderer), 필요 시 CDN import map 사용
- 렌더링: **화면에 보이는 WebGL `<canvas>` 딱 하나**, 모든 UI도 WebGL 안에서 표시
- 조작: 태블릿 터치 우선, 개발용 키보드 지원

## 2. 핵심 재미와 위험

**핵심 루프:** 주문 확인 → 재료 운반 → 작업대 작동 → 대기 중 다른 일 처리 → 완성품 납품 → 다음 주문.

재미의 중심은 제작 지식 암기가 아니라 **동선 선택, 작업대 점유, 대기 시간 활용**이다.

### 가장 큰 설계 위험

실제 각궁 제작은 상당 부분 순차적이다. 주문 한 개만 만들면 기다림과 운반이 반복되는 심부름 게임이 된다. 따라서 프로토타입에서는 **두 개 이상의 주문을 겹쳐 처리**하고, 작업대에 처리 시간이 생기는 구조를 시험한다. 그래도 재미가 없으면 제작 소재를 과감히 포기한다.

## 3. 제작 소재와 고증 구분

박물관 전시에서 소개된 제작 단계(예: 재료 손질, 활 몸체 만들기, 물소뿔 붙이기, 심줄 올리기, 건조, 해궁, 화피단장, 완성)는 **문화 콘텐츠의 참고 자료**다.

**게임 속 10초 건조, 버튼 한 번으로 뿔 붙이기, 재료 조합 순서, 제한 시간은 게임용 축약/창작 규칙**이며 실제 제작 시간·공법을 재현하지 않는다. 화면의 정보 패널에서도 이를 명시한다. 고증 문구와 도구 명칭은 박물관 자료로 최종 확인한다.

## 4. 플레이어 행동

- 이동: 가상 조이스틱 또는 화면 좌측 드래그. 개발 중 WASD 지원
- 집기/놓기: 근처 물건에 접근 후 우측 큰 액션 영역 탭
- 작업: 재료를 들고 해당 작업대에서 액션 탭
- 납품: 완성품을 출고대에 놓기
- 손에는 한 번에 물건 하나만 들 수 있다

태블릿에서 작은 물체를 정밀하게 클릭하게 하지 않는다. 근접한 대상 중 가장 적합한 물체를 자동 강조한다.

## 5. 첫 프로토타입용 최소 제작 체인

**실제 제작 절차가 아닌 게임용 간소화 체인**이다.

1. `몸체 재료`를 `몸체 작업대`에 놓는다 → 5초 후 `활 몸체` 생성
2. `활 몸체`와 `뿔 재료`를 `결합대`에 순서대로 넣는다 → 6초 후 `결합된 몸체` 생성
3. `결합된 몸체`를 `마감대`에 놓는다 → 4초 후 `완성 활` 생성
4. 출고대에 납품한다

작업대는 각 1개, 진행 중 다른 재료 운반 가능. 작업대는 진행 상황을 3D 게이지로 표시한다.

> MVP에는 실제 전시의 8단계를 모두 넣지 않는다. 재미가 검증되면 전시 설명과 추가 단계 확장 여부를 판단한다.

## 6. 주문·점수·난이도

- 시작 주문 2개, 이후 주문은 최대 2개까지 동시 표시
- 한 판 180초(테스트하며 조정)
- 납품 1개당 100점
- 주문 만료 시 0점 처리하고 다음 주문으로 교체(감점은 MVP에서 제외)
- 마지막 20초에 새 주문 생성 중단
- 목표는 최고 점수 갱신

### 난이도 단계

- 0~40초: 작업대와 운반 익히기, 첫 주문 1개
- 40~110초: 주문 2개 겹치기
- 110~180초: 같은 작업대를 요구하는 주문으로 작업 순서 고민

## 7. 공간 설계

작은 정사각형 공방 1개. 고정된 탑다운 사선 카메라.

- 왼쪽: 재료 창고(몸체, 뿔)
- 중앙: 몸체 작업대, 결합대
- 오른쪽: 마감대, 출고대
- 이동 동선이 최소 한 번은 교차하도록 배치
- 플레이어와 작업대는 단순 로우폴리 메시로 시작

초기에는 캐릭터 애니메이션 없이 캡슐/박스 캐릭터로 충분하다.

## 8. 화면 흐름

`TITLE → TUTORIAL → PLAYING → RESULT → TITLE`

모두 하나의 WebGL 렌더러와 캔버스에서 씬 상태로 전환한다. 별도 HTML 페이지, HTML 버튼, DOM 점수판 사용 금지.

- TITLE: 3D 공방 배경 + 텍스처 글자 + 시작 버튼
- TUTORIAL: 이동·집기 안내(짧게)
- PLAYING: 주문, 타이머, 점수, 작업대 진행 표시
- RESULT: 납품 개수, 점수, 다시 하기

## 9. 그래픽스 과제 필수 제약

1. `index.html`에는 화면 표시용 `<canvas>` 하나만 둔다.
2. CSS는 캔버스 전체 화면 처리만 허용한다.
3. UI는 WebGL 안에서 Plane/Sprite/메시로 표시한다.
4. 텍스트는 메모리상의 2D canvas에 그려 `THREE.CanvasTexture`로 변환한다. 추가 2D 캔버스를 DOM에 붙이지 않는다.
5. 버튼은 캔버스 좌표 히트테스트 또는 `THREE.Raycaster`로 판정한다.
6. 씬 전환은 게임 상태 전환으로 구현한다.
7. 터치 입력은 `pointer` 이벤트를 사용한다.
8. 그래픽스 과목 성과로 좌표 변환, 카메라, 조명, 텍스처, 레이캐스팅 등을 명시적으로 구현·기록한다.

## 10. 성공 판정

- 10초 안에 이동과 집기 방법을 이해할 수 있는가?
- 1분 안에 첫 완성품을 납품할 수 있는가?
- 두 주문이 겹쳤을 때 작업 순서를 고민하게 되는가?
- 기다리는 시간보다 직접 행동하는 시간이 많은가?
- 플레이어가 한 판 더 하려 하는가?

세 번째와 네 번째 조건이 실패하면 주문/작업대 구조를 재설계한다.

## 11. 범위 밖

멀티플레이, 실제 8단계 정밀 공정, 현실적인 재료 변형 물리, 온라인 랭킹, 캐릭터 음성, 방 여러 개, 복잡한 AI NPC는 MVP에서 제외한다.
