# AGENTS.md — 각궁 공방 대소동

## 목표와 기준
GAME_DESIGN.md를 제품 기준으로 사용한다. 한 공방을 함께 보는 **2인 로컬 협동 게임**이다. 1인용/분할 화면/온라인 멀티플레이로 변경하지 않는다. TASKS.md에는 구현과 실제 검증을 별도로 기록한다.

## 반드시 지킬 기술 제약
- 순수 WebGL API와 일반 JavaScript만 사용한다. Three.js, 외부 엔진, CDN, API, 네트워크 자산을 사용하지 않는다.
- Node/npm/Vite/빌드는 플레이에 필요하지 않아야 한다. classic script와 상대 경로로 index.html 더블 클릭 실행을 지원하도록 작성한다. ES module/fetch 기반 로딩을 도입하지 않는다.
- 화면에 붙는 요소는 WebGL canvas 하나다. HUD/글자/버튼/조이스틱/결과 화면을 같은 캔버스에 렌더링한다. 메모리의 2D canvas로 텍스트 텍스처를 만드는 것은 허용한다. DOM UI 및 브라우저 alert UI를 추가하지 않는다.
- 공유 직교 카메라 하나로 공방 전체를 표시한다. 현재 렌더러는 CPU 직교 좌표 투영과 WebGL 삼각형 배치 렌더링을 사용한다.

## 게임 불변 조건
- P1 WASD/F/G, P2 방향키/Enter/오른쪽 Shift. 태블릿에서는 플레이어별 조이스틱/행동/내려놓기를 동시에 독립적으로 사용할 수 있어야 한다.
- 각자 한 물건. 바닥 드롭과 두 사람 모두의 회수 지원.
- 몸체 재료 → 가공 5초 → 활 몸체 + 뿔 재료 → 결합 6초 → 결합 몸체 → 마감 4초 → 완성 활 → 출고.
- 작업대 idle/processing/ready, 결과는 빈손으로 집기. 기다리는 동안 이동/다른 작업 가능.
- 공동 주문 최대 1개, 180초, 납품당 100점. 마지막 20초 주문 보충 중단.
- 상대 접근 속도 3 world unit/s 초과의 충돌은 둘 다 0.7초 넘어짐, 소지품 낙하, 기상 후 1초 보호. 느린 접촉은 위치만 분리한다.
- TITLE/TUTORIAL/PLAYING/RESULT. 재시작 시 모델 전체 초기화.

## 구현 및 검증
- game.js는 DOM/WebGL 없이 게임 규칙을 담당한다. render.js는 WebGL, controls.js는 키보드/포인터, main.js는 화면 상태와 캔버스 UI를 연결한다.
- 이동/시간은 delta time, 충돌은 작은 substep을 사용한다. 포인터 ID를 분리하고 cancel/lostcapture/blur/화면 전환에서 입력을 정리한다.
- 기존 자료는 archive/before-coop-20261105에 보존했다. 기존 저장소의 다른 변경 사항을 되돌리거나 자동 커밋하지 않는다.
- 개발용 tests/*.cjs는 선택적이다. 테스트에 사용한 Node는 게임 실행 의존성이 아니다.
- 브라우저/실물 태블릿/오프라인 직접 실행을 실제로 수행하지 않았다면 통과라고 적지 않는다. 문서의 과거 검증을 새 구현의 검증으로 옮기지 않는다.
- 실제 각궁 공예와 게임용 축약을 구분한다. 역사적 공법/시간은 확인한 출처가 없으면 사실로 단정하지 않는다. 외부 자산을 도입하면 출처/라이선스와 오프라인 포함 여부를 기록한다.

## 1년 주문·방향 운반 개정
현재 규칙은 동시 주문 한 건, 납기 45초입니다. 게임 속 1년(365일)을 45초로 압축한 주문 달력을 표시합니다. 한 판은 180초, 가공/결합/마감은 5/6/4초, 마지막 20초 주문 보충 중단은 유지합니다. 실제 제작에 약 1년이 걸리는 사례를 소재로 한 게임 규칙이며 모든 실제 각궁이 정확히 365일 걸린다는 뜻이 아닙니다. 완료 시 달력은 다음 주문의 1년으로 초기화됩니다. 작업대는 x=-7.2/0/7.2, z=-3.7/3.7의 2행 3열로 배치합니다. 운반 물건은 캐릭터의 앞쪽에 위치하고 방향에 맞춰 함께 회전합니다. 등 뒤쪽으로 향한 물건은 캐릭터보다 먼저 그립니다. 구체적인 변경/검증/출처는 docs/year-order.md 참조.
