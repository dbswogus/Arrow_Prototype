# 데굴데굴 옹기: 내 자리로 돌아가는 길

> 한국어 게임 기획서 · 2026-11-07  
> 문서 상태: 확정 요구사항 정리 및 구현 기준. 소장품 식별 정보·사진·권리 정보는 확인 전까지 placeholder로 유지한다.

## 1. 프로젝트 개요

| 항목 | 내용 | 상태 |
|---|---|---|
| 소재 | 부천시박물관 옹기 소장품 | 확정 |
| 주요 이용자 | 초등학생 | 확정 |
| 이용 환경 | 태블릿 터치, 가로 화면 기준 | 태블릿 확정 / 가로 화면은 구현 기준안 |
| 플레이 시간 | 한 회차 약 3~5분 | 확정 |
| 장르 | 2.5D 옹기 물리 퍼즐 | 확정 |
| 목표 | 옹기가 박물관 개관 전에 자신의 전시대로 돌아가도록 길을 기울여 안내하기 | 확정 |
| 입력 | 왼쪽 회전·오른쪽 회전 버튼 두 개, 점프 없음 | 확정 |
| 실행 | Three.js 로컬 파일 사용, 오프라인 실행, 단일 WebGL canvas | 확정 |

아이들이 두 버튼만으로 경사와 구름 운동의 관계를 익히고, 실제 박물관 소장품의 모습과 쓰임을 만나는 짧은 체험을 만든다. 실물 소장품의 역사적 사실은 검증된 자료만 사용한다.

## 2. 결정사항과 미확정사항

### 2.1 확정한 핵심 결정

- 실제 소장품 사진 세 종류를 보여주고, 하나를 선택해 시작한다.
- 실제 사진은 선택·설명용 자료이며, 이동하는 플레이어는 별도의 3D 옹기 모델이다.
- 옆에서 보는 고정 카메라와 횡방향 진행을 사용한다.
- 두 회전 버튼으로 길을 기울인다. 누르는 동안 회전하고, 놓으면 현재 각도를 유지한다.
- 회전 범위는 기준 자세에서 −25°~+25°이며 자동으로 수평 복귀하지 않는다.
- 중력과 관성으로 움직이고 점프·직접 이동 입력은 없다.
- 공방 → 가마 앞 → 전시실의 세 단계를 거친다.
- 실패하면 체크포인트에서 복귀한다.
- 선택 화면부터 결과 화면까지 모든 UI를 하나의 WebGL canvas 안에 표시한다.
- Three.js는 로컬에 포함한다. npm, Vite, CDN을 사용하지 않는다.

### 2.2 구현 기준안 및 확인할 사항

다음 내용은 개발 가능한 형태로 구체화한 기준안이며, 별도 승인된 사실이나 최종 수치로 간주하지 않는다.

| 항목 | 현재 기준안 / 확인할 내용 |
|---|---|
| 사진 세 종류 | 소장품명·사진·소장번호·사용 조건 확인 필요 |
| 설명 문구 | 박물관의 공식 자료와 담당자 확인 후 확정 |
| 모델 외형 | 공통 충돌체를 사용하는 세 가지 외형 또는 공통 모델 중 선택 |
| 회전 대상 | 각 단계의 길·장애물·목표를 하나의 스테이지 루트로 묶어 함께 회전 |
| 회전 속도 | 초당 약 18°를 초기값으로 시험 후 조정 |
| 물리 수치 | 중력, 마찰, 감쇠, 최대 속도는 실제 태블릿에서 조정 |
| 단계 길이 | 단계별 약 45~70초, 선택·설명·결과를 포함해 3~5분 목표 |
| 배포 환경 | 외부 인터넷이 필요 없는 현장 로컬 서버 방식 우선 검토 |
| 소리 | 선택 사항. 없어도 모든 정보를 이해하고 완료할 수 있도록 구성 |

## 3. 스토리와 진행 동기

박물관이 문을 열기 전, 작은 옹기가 잠에서 깨어난다. 전시 준비 중 자신의 자리에서 떨어져 공방 체험 공간까지 와 버렸다. 곧 관람객이 들어올 시간이다. 옹기는 공방을 지나 가마 앞을 건너, 이름표가 기다리는 전시실로 돌아가야 한다.

플레이어는 길을 조금씩 기울여 옹기의 귀가를 돕는다. 옹기가 자신의 전시대에 도착하면 선택한 실제 소장품 사진과 짧은 설명이 나타난다.

### 화면별 이야기 문구 기준안

| 시점 | 문구 |
|---|---|
| 시작 | “곧 박물관이 문을 열어요. 내 자리까지 데려다줄래?” |
| 공방 | “천천히 기울이면 데굴데굴 움직일 수 있어!” |
| 가마 앞 | “빠르면 지나칠 수 있어. 반대로 기울여 속도를 줄여 봐!” |
| 전시실 | “저기 내 이름표가 보여! 조금만 더!” |
| 완료 | “제자리 도착! 이제 친구들을 만날 준비가 됐어.” |

시간은 이야기의 동기이며, 초기 버전에는 강제 제한 시간을 두지 않는다. 옹기가 생명을 얻었다는 설정과 이동 경로는 창작이며, 실제 박물관의 공간 배치나 소장품 이력으로 안내하지 않는다.

## 4. 소장품 사진 세 종류와 설명

### 4.1 현재 자료 상태

**현재 문서에는 개별 소장품을 특정할 근거와 사용 허가가 확인된 사진이 없다.** 아래 세 슬롯은 선택 화면의 구조를 위한 placeholder이다. 임의의 옹기 사진을 부천시박물관 소장품으로 표시하지 않는다.

| 슬롯 | 개별 명칭 | 사진 | 선택 화면 설명 | 권리 상태 |
|---|---|---|---|---|
| A | `[소장품 A 공식 명칭 확인 예정]` | `[사진 A placeholder]` | `[공식 자료 확인 후 쓰임·모양 특징 1~2문장 작성]` | `[출처·권리자·라이선스·허가 확인 전 / 사용 보류]` |
| B | `[소장품 B 공식 명칭 확인 예정]` | `[사진 B placeholder]` | `[공식 자료 확인 후 쓰임·모양 특징 1~2문장 작성]` | `[출처·권리자·라이선스·허가 확인 전 / 사용 보류]` |
| C | `[소장품 C 공식 명칭 확인 예정]` | `[사진 C placeholder]` | `[공식 자료 확인 후 쓰임·모양 특징 1~2문장 작성]` | `[출처·권리자·라이선스·허가 확인 전 / 사용 보류]` |

최종 세 종류는 초등학생이 형태 차이를 알아보기 쉽고, 짧은 설명으로 쓰임을 전달할 수 있는 소장품을 우선한다. 이 기준이 특정 유물의 소장 여부를 의미하지는 않는다.

### 4.2 사진 교체 전 확인 절차

1. 공식 소장품 자료에서 소장 여부, 공식 명칭, 소장번호, 설명을 확인한다.
2. 원본 사진의 출처 URL, 제공 기관, 촬영자·권리자, 확인 날짜를 기록한다.
3. 해당 사진에 적용되는 라이선스와 출처 표기 조건을 개별적으로 확인한다.
4. 게임 내 삽입, 오프라인 파일 동봉, 현장 공개, 크롭·리사이즈 등 실제 사용 범위가 허용되는지 확인한다. 명확하지 않으면 담당자에게 허가를 받는다.
5. 확인 근거와 허가 기록을 보관하고, 허용된 범위 안에서만 로컬 파일로 포함한다.

웹에서 열람하거나 내려받을 수 있다는 이유만으로 사용 허가가 있다고 판단하지 않는다. 확인 전에는 개발 화면에도 placeholder를 사용한다. 본 문서 작성 범위에는 사진 다운로드나 허가 취득이 포함되지 않았다.

### 4.3 사진과 3D 모델의 분리

- **사진:** 선택 카드, 소장품 설명, 완료 화면에서 실제 소장품을 소개한다.
- **3D 모델:** 플레이 중 구르는 옹기 캐릭터를 표현한다. 사진을 구체 표면에 붙여 대체하지 않는다.
- **물리 충돌체:** 시각 모델과 분리한 단순한 원형 단면 충돌체를 사용한다. 세 선택지의 이동 성능은 동일하게 맞춘다.
- 모델이 실물의 정확한 복원이 아니라면 “소장품에서 영감을 받은 게임용 캐릭터”라고 안내한다.
- 소장품별 데이터는 명칭, 설명, 사진 경로, 출처, 권리 표기, 모델 식별자를 별도 필드로 보관한다.

## 5. 화면과 카메라

3D 모델과 조명으로 깊이감을 주되, 물리 이동은 X-Y 평면으로 제한한다. Z축 이동과 화면 밖 방향으로의 회전을 막는다.

**횡스크롤의 의미는 옆에서 보는 좌우 진행 방식으로 한정한다.** 카메라는 각 단계 동안 움직이지 않으며, 자동 추적·팬·줌·사용자 카메라 회전은 없다. 단계 전체와 ±25° 회전 범위가 들어오는 구도를 잡고, 다음 단계로 전환할 때만 새 고정 구도를 적용한다. 실제 카메라 스크롤을 추가하려면 고정 카메라 결정과 함께 별도 재검토한다.

회전 축은 화면 깊이 방향인 Z축이다. 옹기는 스테이지에 부착하지 않고 독립된 물리 객체로 유지한다. 중력은 항상 화면 아래 방향으로 작용한다. 단계의 길과 목표가 함께 회전하면서 중력에 대한 경사가 변한다.

## 6. 조작과 물리 규칙

| 입력 | 동작 |
|---|---|
| 왼쪽 회전 버튼을 누르는 동안 | 스테이지를 반시계 방향으로 회전 |
| 오른쪽 회전 버튼을 누르는 동안 | 스테이지를 시계 방향으로 회전 |
| 버튼을 놓음 | 현재 각도 유지 |
| 두 버튼을 동시에 누름 | 회전 입력 0, 현재 각도 유지 |
| −25° 또는 +25° 도달 | 해당 방향으로 더 회전하지 않음 |

버튼은 옹기의 이동 방향이 아니라 **스테이지 회전 방향**을 뜻한다. 곡선 화살표와 “왼쪽으로 기울이기 / 오른쪽으로 기울이기” 안내로 의미를 전달한다. 옹기는 각도와 현재 속도에 따라 움직이므로 반대쪽을 눌러도 즉시 역주행하지 않는다.

- 점프, 스와이프 이동, 화면 드래그, 기기 기울임 센서는 사용하지 않는다.
- 중력으로 경사 아래쪽으로 가속하고, 관성 때문에 평평한 구간에서도 잠시 굴러간다.
- 반대 경사는 제동과 방향 전환에 사용한다. 회전으로 옹기를 튕겨 넘기는 기술은 요구하지 않는다.
- 각도 변경은 연속적으로 처리하며 충돌체도 같은 변환을 사용한다. 겹친 물체를 강제로 밀어내는 힘으로 진행하지 않게 한다.
- 고정 시간 간격으로 물리를 계산하고, 느린 프레임에서는 세부 계산 또는 연속 충돌 검사로 바닥 관통을 방지한다.
- 터치가 버튼 밖에서 끝나거나 취소되고, 앱이 비활성화될 때도 눌림 상태를 해제한다. 비활성화 중 물리는 일시 정지한다.

## 7. 맵 공통 설계 원칙

**모든 필수 경로는 점프 없이 바닥 접촉을 유지한 채 굴러서 통과할 수 있어야 한다.** 낙하 후 반대편으로 날아가는 구조, 빈틈 뛰어넘기, 수직 턱 오르기, 공중 발판은 배제한다.

- 길은 연속된 바닥·완만한 경사·둥근 연결부로 구성한다.
- 회전 가능한 최대 각도 안에서 각 오르막의 실효 경사가 진행 방향 내리막으로 바뀌도록 설계한다.
- 초기 기준은 국소 오르막 약 10° 이하, 플레이어 지름을 D라고 할 때 통로 여유 높이 1.5D 이상이다. 최종 통과 여부는 마찰과 충돌체를 포함한 실험으로 판단한다.
- 깊은 홈은 얕고 넓은 곡면으로 바꾸고, 막힌 벽은 경사로로 우회한다. 이음새에는 충돌 가능한 틈이나 돌출 턱을 남기지 않는다.
- 목표는 평평한 정지면과 낮은 끝막이로 구성한다. 목표 안에서 낮은 속도로 잠시 머무르면 완료 처리한다.
- 진행 필수 구간에서는 관성으로 도약해야만 성공하는 상황이 없어야 한다. 멈춘 상태에서도 적절한 회전 입력으로 다시 진행할 수 있어야 한다.

## 8. 세 단계 맵 설계

### 8.1 1단계 — 공방: 기울이면 굴러가요

**목표:** 버튼과 경사의 관계를 안전하게 익힌다.

경로: `출발 받침 → 넓은 완만한 길 → 낮고 둥근 언덕 → 평평한 쉼터 → 출구`

처음에는 버튼 그림과 함께 한 문장 안내를 보여준다. 시작 부분은 넓고 평평하며, 낮은 언덕은 스테이지를 기울이면 정지 상태에서도 넘을 수 있게 한다. 쉼터를 체크포인트로 사용한다. 공방 도구는 배경 장식으로 두고 길을 막지 않는다.

**점프 없는 수정:** 작업대 사이의 틈은 연속된 판길로 잇고, 작업대 높이 차는 긴 경사로로 연결한다. 수직 단차와 뛰어넘는 구덩이는 두지 않는다.

### 8.2 2단계 — 가마 앞: 속도를 조절해요

**목표:** 관성과 반대 방향 기울이기를 이용한 제동을 익힌다.

경로: `진입 쉼터 → 완만한 내리막 → 넓고 얕은 곡면 바닥 → 제동 구간 → 출구`

가마는 배경에 배치하고 화염이나 뜨거운 구간을 필수 통과 장애물로 사용하지 않는다. 내리막 뒤에는 충분한 제동 거리를 둔다. 제동 구간을 지난 안전한 평지에 체크포인트를 배치한다. 첫 진입 때 “반대로 기울이면 천천히 멈출 수 있어!”를 표시한다.

**점프 없는 수정:** 가마 앞 끊긴 다리는 고정된 연속 다리로 바꾸고, 좁은 구멍이나 깊은 V자 홈은 제거한다. 내리막 끝을 위로 튀어 오르는 발사대 형태로 만들지 않는다.

### 8.3 3단계 — 전시실: 내 자리에 멈춰요

**목표:** 마지막 경사를 통과하고 전시대 안에 안정적으로 정지한다.

경로: `전시실 입구 → 낮은 굴곡 길 → 전시대 진입 쉼터 → 긴 완만한 경사로 → 목표 정지면`

입구와 전시대 진입 쉼터에 체크포인트를 둔다. 선택한 소장품의 이름표 또는 확인 전 placeholder로 목표를 표시한다. 전시대 끝에는 낮은 끝막이를 두어 실수로 지나치지 않도록 한다.

**점프 없는 수정:** 전시대는 수직으로 올라가는 받침 대신 긴 경사로로 연결한다. 경사로는 최대 회전 범위에서 중력으로 오를 수 있어야 하며, 입구에 충돌 턱을 두지 않는다. 목표 정지면은 옹기가 들어간 뒤 각도를 조절해 충분히 멈출 수 있는 길이로 만든다.

## 9. 실패와 체크포인트

낙하 경계 밖으로 벗어나거나 물리 오류로 복귀할 수 없는 상태가 되면 마지막 체크포인트로 자동 복귀한다. 횟수 제한과 생명 차감은 없다. 깨지는 표현 대신 짧은 화면 전환과 “괜찮아, 여기서 다시 해 보자!”를 사용한다.

복귀 시 위치, 선속도, 회전 속도, 스테이지 각도를 함께 초기화한다. 각도는 해당 체크포인트에 저장된 안전한 값으로 복원하고, 활성 터치도 해제한다. 복귀 위치에 충돌 겹침이나 즉시 낙하가 없어야 한다.

단순히 잠시 멈춘 상태는 실패로 판단하지 않는다. 일정 시간 진행이 없으면 두 버튼 사용법을 다시 보여주고, 회복 불가능한 끼임이 확인된 경우에만 자동 복귀한다.

## 10. UI와 화면 흐름

`시작 → 소장품 3종 선택·설명 → 조작 안내 → 공방 → 가마 앞 → 전시실 → 소장품 소개·완료`

모든 버튼, 문자, 사진, 안내, 진행 표시, 결과 화면은 **단일 WebGL canvas 내부**에서 렌더링한다. HTML 버튼·DOM 텍스트·별도 UI canvas를 화면 위에 겹치지 않는다. 문자는 로컬 글꼴과 내부 텍스처 등으로 준비하고, 별도 화면 요소를 추가하지 않는다.

- 플레이 화면 하단에는 두 개의 큰 회전 버튼만 둔다. 추가 점프·이동·재시작 버튼은 없다.
- 선택·시작·다시 하기 등 화면 전환용 터치 요소는 각 메뉴에서만 사용한다.
- 상단에는 현재 단계와 세 단계 진행 상태를 표시한다. 각도 표시는 기울어진 길 그림으로 간단히 표현한다.
- 사진 출처와 권리 표기는 소장품 설명 화면 안에서 읽을 수 있게 제공한다.
- 태블릿에서 읽기 쉬운 글자, 높은 대비, 넓은 터치 영역을 확보한다. 색만으로 상태를 구분하지 않는다.
- canvas 크기와 표시 비율이 바뀌어도 실제 버튼 위치와 터치 판정이 일치해야 한다.

## 11. 기술 구성과 오프라인 실행

### 11.1 파일 구성 기준안

```text
index.html
src/
  main.js
  game.js
  physics.js
  stages.js
  ui.js
  collection-data.js
vendor/
  three/               # 선택한 버전의 Three.js 및 필요한 로컬 의존 파일
  licenses/            # 포함 라이브러리의 라이선스 고지
assets/
  photos/              # 허가 확인된 사진 또는 명시적인 placeholder
  models/
  fonts/
  audio/               # 사용하는 경우에만 포함
```

### 11.2 실행 원칙

- 빌드 과정 없이 HTML과 JavaScript 및 정적 자산으로 구성한다. npm 설치와 Vite 실행을 전제로 하지 않는다.
- Three.js의 선택 버전을 프로젝트에 직접 포함하고 상대 경로로 불러온다. CDN, 원격 글꼴, 외부 API, 분석 서비스에 의존하지 않는다.
- 추가 모듈을 쓰면 그 의존성도 로컬에 포함하고 경로를 확인한다. 버전과 라이선스 고지를 보관한다.
- 오프라인은 **인터넷 연결 없이 동작**한다는 의미이다. 브라우저의 로컬 파일 접근 제한이 있으므로 파일 더블클릭 실행은 보장하지 않는다.
- 배포 시 정적 파일을 제공하는 로컬 서버 또는 사전에 검증한 전용 실행 환경을 함께 정한다. 태블릿 브라우저가 인터넷 없이 해당 환경에 접속할 수 있는지도 현장에서 확인한다.
- 첫 실행부터 인터넷을 끊은 상태로 사진·글꼴·모델과 모든 화면이 정상 로드되어야 한다.

물리는 Three.js 렌더링과 분리한다. 평면 내 원형 충돌체와 선분·곡면 근사 바닥으로 먼저 구현하고, 별도 물리 라이브러리가 필요하면 로컬 포함 여부와 배포 크기를 검토한다. 물리 라이브러리 선택은 미확정이다.

## 12. 구현 우선순위

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 최소 물리 시제품 | 고정 카메라, 두 버튼, ±25°, 놓으면 각도 유지, 중력·관성 구현 |
| 2 | 점프 없는 경로 검증 | 단순 모델로 세 단계의 모든 필수 구간을 연속 주행 |
| 3 | 실패·체크포인트 | 안전한 복귀와 속도·각도 초기화, 진행 불가 상태 회복 |
| 4 | 단일 canvas UI | 선택부터 완료까지 canvas 안에서 조작 가능 |
| 5 | 소장품 자료 확정 | 세 종류의 명칭·설명·사진·출처·사용 허가 확인 |
| 6 | 시각 표현 | 3D 옹기, 공방·가마 앞·전시실 배경, 사진 소개 적용 |
| 7 | 현장 검증 | 실제 태블릿, 오프라인 첫 실행, 초등학생 체험으로 조정 |

자료 확인은 개발과 병행한다. 허가가 지연되면 placeholder로 기능 검증을 마치되, 실제 사진이 포함된 공개 버전은 권리 확인 후 제공한다.

## 13. 검증 항목과 수용 기준

### 조작·물리

- [ ] 두 회전 버튼 외에 플레이에 필요한 입력이 없다. 점프 없이 세 단계 완료가 가능하다.
- [ ] 누르는 동안만 회전하고, 놓으면 각도가 유지되며 ±25°를 넘지 않는다.
- [ ] 동시 입력, 버튼 밖에서 손 떼기, 터치 취소, 앱 전환 후에도 입력이 고정되지 않는다.
- [ ] 중력 방향이 유지되고 관성·제동이 일관되게 작동한다.
- [ ] 각 필수 오르막은 직전 정지 상태에서도 허용 각도로 통과할 수 있다.
- [ ] 최대 속도와 낮은 프레임에서도 바닥 관통·벽 끼임·회전에 의한 비정상 발사가 없다.

### 맵·복귀

- [ ] 세 맵에 필수 도약, 수직 턱, 끊긴 바닥이 없다.
- [ ] ±25° 전체 범위에서 옹기·길·목표가 고정 카메라 안에 보인다.
- [ ] 모든 체크포인트에서 위치·속도·각도가 안전하게 복원된다.
- [ ] 목표 진입과 정지가 재현 가능하며, 완료 판정이 중복 발생하지 않는다.

### 화면·자료·배포

- [ ] 선택·설명·플레이·완료·권리 표기를 포함한 모든 UI가 한 WebGL canvas 내부에 있다.
- [ ] 실제 사진과 이동용 3D 모델이 분리되어 있다.
- [ ] 소장품 세 종류의 명칭·설명·사진 출처·권리 조건·허가 근거가 기록되어 있다.
- [ ] 미확인 자료는 placeholder이며, 확인되지 않은 소장품 정보를 사실처럼 표시하지 않는다.
- [ ] npm, Vite, CDN 없이 배포 파일과 정해진 로컬 실행 환경으로 동작한다.
- [ ] 브라우저 캐시에 의존하지 않는 오프라인 첫 실행과 전체 완료를 확인한다.
- [ ] 실제 태블릿에서 글자·버튼·사진이 읽히고, 두 손가락 입력과 화면 크기 변경이 정상 작동한다.
- [ ] 초등학생 체험에서 안내를 이해하고 3~5분 안에 완료할 수 있는지 확인한다. 지연 구간을 기록해 길이와 물리 수치를 조정한다.
